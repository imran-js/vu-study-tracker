# First release plan

1. Establish typed records, timezone rules, validation, IndexedDB repository, ordered migrations, and atomic backup restore.
2. Build responsive navigation and empty semester onboarding; implement courses, lectures, revision, configurable assessments, sessions, timer, resources, calendars, progress, and settings.
3. Verify integrity rules and UI at desktop/mobile sizes; run production build; prepare GitHub Pages workflow and Windows documentation.

No real academic records are seeded. Personal data exists only in the browser or user-selected backup files. Future adapters must use application actions and domain validation.
